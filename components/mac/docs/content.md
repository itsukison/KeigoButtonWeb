## 0.5 デザイン方針 ★`design.md` からの離脱

**この LP は `design.md` に従いません。** 従った第1版が白黒で地味だったためです。

### なぜそうなったか

`design.md` は「パレットを97%無彩色に保ち、バイオレット `#0447ff` とオレンジ `#ff4704` は
製品ビジュアル内でのみ使う」と明記しています。第1版の地味さはルール違反ではなく、
**ルールを正確に守った結果**でした。参照元を差し替えても、この禁止を外さない限り同じ結果になります。

外したのは**この禁止1行だけ**です。色そのものは元からシステム内にありました。

### 採用：Willow 系 + バイオレット主役

| | 内容 |
|---|---|
| 構造・書体レジスター | **Willow**（`19.30.36` / `.47` / `.56` / `19.31.09`） |
| 色 | **`#0447ff` をブランドカラーに昇格**。Willow の淡いラベンダーではなく、`#0447ff` 自体から起こしたティントで全面を統一 |
| 見出し | Inter 300 → **600**、トラッキング -0.02em → **-0.035em** |
| 地 | eggshell `#fdfcfc` → **純白 + バイオレットティント** |
| 影 | ほぼ無し → **実影あり**（ブランド色を混ぜた青みの影） |

### Poke を採らなかった理由

1. **地味さが直りません。** Poke もクリーム地の低彩度で、eggshell とほぼ同じ明度帯です。Poke の華やかさはセリフ書体と手描き的な余白から来ていて、色から来ていない
2. Poke は「友達のように振る舞うアシスタント」を売る製品で、あの編集的な軽さは人格を伝えるためのものです。**敬語ボタンに人格はありません**。押すと文章が整うボタンです
3. アクセシビリティ権限を求める製品なので、日本のビジネス層に対しては軽さより確からしさが要ります

### Willow に寄せすぎるリスクと、その回避

`AGENTS.md` §1 の通り、インタラクション自体を Willow から借りています。LP まで同じ見た目に
すると模倣に見えるため、**色で意図的に外しています** — Willow はラベンダー、うちは `#0447ff`。
構造は Willow、色は自前、という切り分けです。

### 副次効果：`AGENTS.md` §12 の宿題が1つ片付く

§12 は「iOS コンテナは Bikey（紫 + Liquid Glass）、Mac は design.md。ひとつの製品に見えない」
を公開前の決定事項として挙げています。Mac 側をバイオレット基調にしたことで、**この2面が
初めて縁続きになりました**。iOS 側の紫の実際の色値がわかれば、さらに寄せられます。

### `design.md` から残したもの

捨てたのは**パレットと書体ウェイトだけ**です。以下は継続しています。

- 4px ベースのスペーシングスケール
- 9999px のピルボタン（製品のバー形状と韻を踏むため、むしろ重要）
- 20/24px のカード角丸
- セクション間 96〜120px の余白リズム
- 1280px の最大幅

### 動かしてはいけない1点

**製品ビジュアル内のバーはダークのまま**です（`AGENTS.md` §8 の overlay ramp）。
実機がダークであること、そして**この明暗差が「他アプリの上に乗っている」感を作っている**ためです。
淡いバイオレット地の上に置くことで、第1版のクリーム地より対比はむしろ強まっています。

**オレンジ `#ff4704` は生成中キャプセルのグラデーション1箇所のみ**に残しました。
かつてバイオレットが担っていた「唯一の色」の役割を、オレンジが引き継いだ形です。

## 1. ストーリーの背骨（これが通っていれば LP は成立する）

一文で：**「いま書いているその場所で、自分が作ったボタンを押すだけで文章が整う。コピーも貼り付けもアプリの切り替えもない。」**

読み手が上から下へ辿る 6 手：

1. **痛み** — 日本語のビジネス文は「書く」より「書き直す」に時間がかかる。しかも直すたびに ChatGPT に貼って、返ってきたものをまた貼り戻している。
2. **転換** — その往復自体が要らない。文章はいま開いているアプリの中にあるのだから、その場で書き換わればいい。
3. **仕組み** — 画面下のバーにホバー → 自分のボタンが並ぶ → 押す → **その場で置き換わる**。3 コマで見せる。
4. **範囲** — Mail / Slack / Gmail / Notion / Chrome / Word、テキストを打てる場所ならどこでも。
5. **連続性** — ボタンは iPhone の「敬語ボタン」で作ったものがそのまま出る。設定し直しは不要。
6. **安心** — アクセシビリティ権限が何に使われるか、文章がどこに行くのかを**先に**説明する。ここを飛ばすと DL しても権限で止まる。

そして CTA：**無料でダウンロード（Mac版）**。

### トーンの決め

- 日本語。敬体（です・ます）。Henji（R7）の口語寄せは**見出し 1 箇所だけ**採用し、本文は落ち着かせる。
- 主語は極力省略。「私たち」は使わない。
- 誇張しない。`design.md` の「editorial restraint over marketing spectacle」がそのまま文体の指針。

## 3. セクション別 詳細（コピー草案つき）

コピーは**そのまま入れられる粒度**で書いています。確定ではなく叩き台です。

### §1 ナビ

浮遊カプセル（R7）。`design.md` の「9999px ピル」を**ナビ自体の形**にすることで、製品の主役（画面下のピル）と韻を踏ませます。これが本 LP の一番のオリジナリティ。

- 背景：`#fdfcfc`、1px `#ebe8e4`、`--shadow-subtle`、上部 24px 固定
- 左：マーク + `敬語ボタン`（Inter 500 / 15px）
- 中：`できること` `使い方` `料金` `FAQ`（Inter 14px / `#000`）
- 右：黒塗りピル `Mac版をダウンロード`（Apple マーク付き）
- スクロールで背景の不透明度だけ上げる。高さは変えない。

---

### §2 ヒーロー ★最重要

**採用は R9（Willow 分割）。** 理由：うちの製品は「他アプリの上に薄いバーが乗る」構造そのものなので、他アプリの画面を背景に製品を合成した図が、説明せずに構造を伝えます。R8（中央寄せ）はバーが小さすぎて何も伝わらないため不採用。

左カラム（60%）：

```
H1（Inter 300 / 48px / -0.96px / #000）
  いま書いている場所で、そのまま整える。

Sub（Inter 400 / 20px / #777169 / 最大 2 行）
  画面下のバーにホバーして、自分のボタンを押すだけ。
  コピーも、貼り付けも、アプリの切り替えもいりません。

CTA（横並び）
  ■ Mac版をダウンロード（黒塗りピル / 無料）
  □ 使い方を見る（アウトラインピル → §5 へアンカー）

Caption（Inter 13px / #a59f97）
  macOS 14 以降 · 無料で使えます · iPhone版「敬語ボタン」と同じアカウント
```

**H1 候補（1 つ選ぶ）**

| 案 | 文言 | 性格 |
|---|---|---|
| A ★推奨 | いま書いている場所で、そのまま整える。 | 動作＝価値。製品構造を一文で言い切る |
| B | コピーしない。貼り付けない。切り替えない。 | 否定の三連。痛みからの入り。強いが冷たい |
| C | あなたの敬語ボタンが、Macの画面の下に。 | iPhone 既存ユーザーに刺さる。新規には弱い |

→ **A を H1、B を §3 の見出しに転用**すると重複せず両方使えます。

右カラム（40%〜、はみ出し可）：ヒーロービジュアル → **アセット A1**

### §3 痛みの提示

中央 1 カラム。短く、間を大きく取る。

```
H2（Inter 300 / 36px）
  コピーしない。貼り付けない。切り替えない。

Body（Inter 400 / 16px / #777169 / 最大 560px）
  文章を直すたびに、選んで、コピーして、別のアプリに貼って、
  返ってきたものをまた貼り戻す。
  1 回 30 秒でも、1 日に何度も繰り返せば、それは仕事になります。

ビジュアルなし。**空白そのものが演出**（`design.md`「generous whitespace」）。

### §4 対応アプリ

R2（Poke）の浮遊アイコン。ロゴ壁の代わり。

```
H2  テキストを打てる場所なら、どこでも。
Body  Mail、Slack、Gmail、Notion、Chrome、Word、メモ。
      アプリごとの設定はありません。
```

- 中央に淡いグラデーションの帯（→ **アセット A5**）を敷き、その上にアプリアイコンを**不規則に**配置（Poke と同じく整列させない）
- アイコンは各社の公式アイコンを使用。**商標利用の可否は要確認**（実務上は「対応アプリの表示」として通ることが多いが、Slack / Notion のブランドガイドは要確認）
- 回避案：アイコンを使わずウィンドウのシルエット（信号機ボタンだけの抽象ウィンドウ）を並べる。安全側

**社会的証明（確定）**
`5,000人以上` を使用します（社内の別集計にもとづく実数として確認済み）。
表記は **「iPhone版「敬語ボタン」は 5,000人以上に使われています」** とし、**iPhone 版の実績であることを明示**します。Mac 版の実績と誤読される書き方（単に「5,000人が使っています」）は避けてください。

### §5 使い方 3 ステップ ★2 番目に重要

R10（Willow 絵コンテ）をそのまま構造採用。ここで理解されなければ DL されません。

```
H2（中央）  3 秒で終わります。
Sub        覚えることは、ホバーして押すことだけ。
```

3 カード横並び（各カードは実スクリーンショット + 番号 + タイトル + 説明）：

| | タイトル | 説明 | ビジュアル |
|---|---|---|---|
| 01 | 書く（または選ぶ） | いつも通りアプリで文章を書きます。直したい部分を選んでも、選ばなくても構いません。 | A2-1 |
| 02 | バーにホバーする | 画面の下のバーにカーソルを乗せると、自分のボタンが並びます。 | A2-2 |
| 03 | 押すと、その場で置き換わる | 押した瞬間に書き換えが始まり、元の文章と入れ替わります。貼り付ける操作はありません。 | A2-3 |

補足行（Inter 13px / `#a59f97`）：
`ボタンにない指示は ✎ から自由入力できます。`

### §6 機能ディープダイブ ×3

R3/R4（Poke）の番号付き交互レイアウト。セクション間は 1px ヘアライン。
左肩に `(1)` `(2)` `(3)`（Geist Mono 13px / `#a59f97`）。

#### (1) 自分のボタンで書き換わる — 画像左／テキスト右

```
H3  ボタンは、あなたが決める。
Body 「敬語に」「短く」「英訳」——よく使う直し方をボタンにしておけます。
     iPhone版で作ったボタンは、そのままMacにも並びます。
CTA  ボタンの作り方を見る →
```
ビジュアル：**A3-1**（ボタン編集画面 = eggshell のメインウィンドウ）

#### (2) 選んでも、選ばなくても — テキスト左／画像右

```
H3  選択しなくても、書き換えられる。
Body 一部を選べばその部分だけ。何も選ばなければ、入力欄の文章まるごと。
     どちらかを選ぶ操作は要りません。
```
ビジュアル：**A3-2**（選択あり／なしの 2 状態を 1 枚に並置）

> これは `AGENTS.md` §5 の `.selection` / `.wholeInput` の話で、**クリップボード方式の競合には原理的にできない**差分です。技術用語は出さずに「選ばなくてもいい」とだけ言えば伝わります。LP 上の最大の差別化ポイント。

#### (3) 生成中の 2.6 秒 — 画像左／テキスト右

```
H3  待つ時間も、製品のうち。
Body 書き換えの間だけ、バーは細いキャプセルに変わります。
     色を使うのは、この一瞬だけです。
```
ビジュアル：**A3-3**（バイオレット→オレンジのグラデーション枠キャプセル）
→ `design.md` の「アクセントは製品ビジュアルのみ」を**そのまま LP の演出に転用**できる唯一の場所。ここで初めて色が出る構成にすると、ページ全体の無彩色が効きます。

### §7 機能グリッド

R12（Willow）。ただし `design.md` は「trust section より下でカードグリッドを使わない」と書いているため、**影なし・タウペ `#f5f3f1`・角丸 20px の平坦カード**に落として system 内に収めます。3 列 × 2 行。

| | タイトル | 説明 |
|---|---|---|
| 1 | どのアプリでも同じ手順 | アプリごとの拡張機能もプラグインも不要です。 |
| 2 | 元に戻せる | 書き換えは各アプリの取り消し（⌘Z）でそのまま戻せます。 |
| 3 | 候補を選べる | 複数の書き換え案から選んで挿入できます。 |
| 4 | ドラッグで移動 | バーの位置は好きなところに置けます。次回も同じ場所に出ます。 |
| 5 | ログイン不要の常駐 | Dock にアイコンは出ません。メニューバーから設定を開けます。 |
| 6 | フルスクリーンでも出る | フルスクリーンのアプリの上でもバーは画面下に留まります。 |

> 3・4・5・6 は `AGENTS.md` に実装記述があります。**2（⌘Z で戻せる）は AX 書き込み経路では成立しますが、クリップボード経由の paste 経路でも同様かは未検証**（§5 の write path 自体が未観測）。実機確認が取れるまで LP に載せないでください。取れなければ差し替え案：「クリップボードを汚しません（書き換え後に元の内容へ戻します）」。

### §8 iPhone との連続

2 カラム。左にテキスト、右にビジュアル（**A4**：iPhone とラップバー が同じボタン列を持っている図）。

```
H2  スマホで作ったボタンが、そのままMacに。
Body iPhone版「敬語ボタン」と同じアカウントでログインするだけ。
     ボタンの並びも文言も引き継がれます。どちらで編集しても、両方に反映されます。

> LP 側の文言はこの節に用意してありますが、**公開時点で公証が通っていることだけ確認**してください。

### 製品ビジュアルはスクリーンショットではなく DOM で再現しています

`AGENTS.md` §4/§8 の値（ダークランプ、28pt/34pt、キャプセル半径、2.6 秒回転）から
CSS で組み直しました。理由は 3 つ：

1. トークンが変わっても追随する
2. どの解像度でも滲まない
3. **静止画では「その場で置き換わる」が表現できない** — ヒーローは
   待機 → ホバー → 生成中 → 置換 を実際に繰り返します

これにより §4 のアセット表から **A1・A3-2・A3-3 が不要**になりました。
残るキャプチャ作業は A2（3 ステップ）・A3-1（ボタン編集画面）・A4（iPhone 実機）だけです。
ただし現状の再現で十分見られる状態なので、**キャプチャは公開のブロッカーではありません**。

### 実装時に判断したこと

- **`--pscale`**：実物のバーは 28pt で、Web 上に原寸で置くと読めません。すべての寸法を
  `--pscale` の倍数で書き、比率を保ったまま拡大しています。**インラインではなくクラス
  （`.pv--lg` `.pv--md` `.pv--sm` `.pv--xs`）で指定**しています。インラインの CSS 変数は
  メディアクエリに勝ってしまい、狭い画面でバーが枠からはみ出したためです。
- **⌘Z の項目を §7 から外しました。** AX 書き込み経路では成立しますが、クリップボード
  経由では未検証で、そもそも `AGENTS.md` が write path 自体を未観測としています。
  代わりに「クリップボードを汚さない」を入れています。実機確認が取れたら戻してください。
- **`--text-display` は 48px。** 56px にすると日本語の H1 が3行に折れ、最後の2文字だけが
  取り残されました。日本語はハイフネーションが効かず全角なので、**ディスプレイサイズを

## 7. 実装メモ（変更時に読む）

- `design.md` の CSS カスタムプロパティは `src/styles/tokens.css` に写してあります。
- **ダークモードは作らない**。`design.md` は light 固定の system。ただし**製品ビジュアル内のバーはダーク**（`AGENTS.md` §8 の overlay ramp）で、この明暗差自体が「アプリの上に乗っている」感を作ります。意図的な対比なので崩さないこと。
- **バイオレット `#0447ff` / オレンジ `#ff4704` を増やさない。** ページ全体で
  §6-(3) の生成中キャプセル 1 箇所だけです。ここまで無彩色で来るからこの一瞬が効きます。
- 影は `--shadow-subtle` のみ。**製品ビジュアルの浮きを表現したくなっても、影を強くしない**（`design.md` Don't）。浮きは背景のタウペとの明度差で作る。
- ヘアラインは `#ebe8e4` 1px。セクション区切りは余白ではなく線を優先（`design.md`：54 箇所で使用されている最頻パターン）。
- アニメーションは**スクロールで薄くフェードイン + 8px 上昇**まで。パララックスや大きな動きは editorial restraint に反する。`prefers-reduced-motion` を必ず尊重。
- OGP：1200×630。A1 のトリミング + H1。
- 計測：PostHog。ただし **`AGENTS.md` §7 の通り、Mac 版は新規 PostHog プロジェクトに送ること**。既存の `Default project`（465060）に混ぜない。LP も同じ新規プロジェクトに送り、`DL クリック → 起動 → 権限許可 → 初回書き換え` をファネルにする。
